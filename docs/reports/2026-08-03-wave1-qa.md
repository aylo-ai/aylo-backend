# Wave 1 — QA strategy audit (read-only)

Date: 2026-08-03 · Scope: `repli-backend` (primary), `aylo-frontend` (secondary) · No code was changed.

## 0. Where I disagree with the brief

1. **The crypto test layer has no subject.** The brief asks for encrypt→decrypt round-trip, nonce, tamper, wrong-key and key-rotation tests. There is no encryption in this codebase. `grep -rn "Fernet\|AESGCM\|encrypt" apps/` matches only a blog seed command. Secrets are stored as plaintext columns: `apps/integration/models.py:32` (`refresh_token = models.TextField()`), the Instagram/Telegram `api_token` on the same model, and `apps/payment/models.py:86` (`card_token = models.TextField()`). **You cannot test crypto that does not exist** — Wave 2 must *build* the encrypted field first; the test list in §2 is written against that future module and is the acceptance criteria for it.
2. **`aylo-frontend` is not "secondary" for auth risk** at 14.77% line coverage — but it is out of my remit to fix.
3. **"10x current peak" is unmeasurable today.** See §5.

## 1. Measured coverage (actually run, not estimated)

Backend, `coverage run --source=apps --branch manage.py test --keepdb` (coverage 7.15.3 installed into a scratch venv; `.venv` untouched — `coverage` is **not** in `requirements.txt`):

```

```

- **Line coverage: 66%** (5520/8361). **61%** including branch coverage.
- Frontend: `npm run test:coverage` → **14.77% lines**, 95 tests / 10 files passing.

**100% line coverage is not the goal and should never be the gate.** The goal is: every security-critical path has a test that *fails if the protection is removed*; business logic has meaningful branch coverage; everything else is on a named exclusion list. Proposed exclusions (documented in `.coveragerc`, not silently dropped): `*/migrations/*`, `*/admin.py`, `*/apps.py`, `config/`, `apps/landing/`, `apps/blog/`, `apps/assistant/services/google.py` (dead — see §2 P1-6).

Credit where due: tenancy/IDOR coverage is genuinely good already — `apps/integration/tests.py:813-1245` and `apps/payment/tests.py:41-479` assert *denial* across tenants, and `apps/shared/tests/test_telegram_webhook_logging.py:21-57` already asserts the bot token never reaches captured log output. The gaps below are elsewhere.

## 3. Test cases (names + Given/When/Then)

### 3.1 Crypto — `apps/shared/tests/test_encrypted_field.py` (blocked on Wave 2 building the field)

| Test | Given / When / Then |
|---|---|
| `test_round_trip_preserves_unicode_and_empty` | Given plaintexts `""`, `"токен"`, `"токен 🔑"` / When stored then re-read / Then identical strings return |
| `test_two_encryptions_of_the_same_plaintext_differ` | Given one plaintext / When encrypted twice / Then ciphertexts differ (nonce is not reused) |
| `test_tampered_ciphertext_raises_and_never_returns_plaintext` | Given a stored value with one flipped byte / When decrypted / Then it raises; assert the plaintext is **not** in the exception text |
| `test_wrong_key_fails_closed` | Given a row encrypted under key A / When read under key B / Then raises — never returns a partial or empty string that a caller could mistake for a real token |
| `test_v1_rows_are_readable_after_a_v2_key_is_added` | Given a v1-encrypted row and a keyring `{v1, v2}` with v2 primary / When read / Then decrypts; When re-saved / Then re-encrypts under v2 |
| `test_token_never_reaches_log_output` | Given `assertLogs` over `apps.integration` / When a webhook and an outbound send run / Then the token substring is absent — extend the existing pattern at `apps/shared/tests/test_telegram_webhook_logging.py:31` |

## 5. Non-functional / load

**Baseline: UNVERIFIED.** No APM, no request-timing middleware, no msgs/day figure. "10x peak" is currently meaningless. Establish it first, in this order: (1) add a `X-Request-Duration` log field and ship p50/p95 per route to Sentry (`sentry-sdk` is already a dependency); (2) derive current peak from production data — `Message` rows per hour grouped by `created_time` over 30 days — that is the true webhook arrival rate; (3) only then run `k6`/`locust` against a staging webhook at 10× that number, asserting p95 and, critically, that the Redis dedup keys and Celery queue depth stay bounded.

## 6. CI wiring

Add a `test` job to both workflows that **blocks deploy**:

1. `python manage.py test --keepdb` (Postgres + Redis services).
2. **Coverage gate on changed files only** — `diff-cover` against `origin/dev`, threshold 80%. Do **not** set a global gate; a 66%→80% backfill mandate produces assertion-free tests. Add `coverage` + `diff-cover` to a new `requirements-dev.txt`.
3. **Secret scanning** — `gitleaks` on the diff, plus a full-history scan once to size P0-1.
4. **Dependency audit** — `pip-audit` (backend) and `npm audit --audit-level=high` (frontend), failing on high/critical.
5. `flake8` (already a dependency, currently unenforced).
